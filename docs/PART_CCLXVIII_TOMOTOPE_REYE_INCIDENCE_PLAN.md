# Part CCLXVIII — Tomotope–Reye Incidence Plan

This note details how to make the Tomotope–Reye correspondence completely explicit,
using only the data already present in this repo.

---

## 1. Matching counts: Tomotope vs Reye

From `tools/tomotope_reye_e8_connection.py` and Monson–Pellicer–Williams (2012):

- Tomotope T:
  - 12 edges
  - 16 triangular 2-faces
- Reye configuration:
  - 12 points
  - 16 lines, each incident with 3 points, each point on 4 lines

So the Tomotope’s `(12,16)` edge/face data matches the Reye `(12₄16₃)` incidence pattern
exactly at the level of counts.

The goal of this part is not to choose a *canonical* labeling, but to set out a
precise algorithm for building an explicit incidence isomorphism once a labeling is
fixed.

---

## 2. Edge and face labels from the 192-flag model

Using `scripts/analyze_tomotope_edges.py` and
`scripts/tomotope_edge_orbit_report.py`, we obtain:

- A list of 12 **edge orbits** `E_0, …, E_11`, each a subset of the 192 flags.
- A list of 16 **face orbits** `F_0, …, F_15`, obtainable similarly by taking
  orbits under the appropriate rank-adjacency generators.

Conceptually:

- Each edge orbit `E_i` corresponds to a single edge of T.
- Each face orbit `F_j` corresponds to a single triangular 2-face of T.

The incidence relation

```
E_i ⊂ F_j    ⇔    there exists a flag (v, e, tri, cell) with e ∈ E_i, tri ∈ F_j.
```

This is computable directly from the flag data.

---

## 3. Building the Tomotope–Reye isomorphism

Step-by-step recipe (to be implemented as a future script):

1. **Compute edge orbits.**  Use the code in `tomotope_edge_orbit_report.py` to
   obtain the 12 edge orbits `E_i`.

2. **Compute face orbits.**  Analogously to edges, define face-orbits as orbits
   of flags under the subgroup generated by `r1, r2, r3` (changing v, e, cell
   while holding the triangle fixed). This yields 16 orbits `F_j`.

3. **Incidence matrix.**  Build a 12×16 0–1 matrix `M` with

   ```
   M[i, j] = 1  iff  ∃ flag whose edge lies in E_i and whose triangle lies in F_j.
   ```

   By construction, every `E_i` will be incident with 4 faces, and every `F_j`
   will be incident with 3 edges, so `M` has row sum 4 and column sum 3.

4. **Relabel to Reye.**  Fix any standard labeling of the Reye configuration
   `(P_0,…,P_11 ; L_0,…,L_15)` with its incidence matrix `R`.

   - Find permutations `σ_edges ∈ S_12` and `σ_faces ∈ S_16` such that

     ```
     M[σ_edges(i), σ_faces(j)] = R[i, j] for all i, j.
     ```

   - This makes the bijections

     ```
     edge E_i ↔ point P_{σ_edges^{-1}(i)}
     face F_j ↔ line  L_{σ_faces^{-1}(j)}.
     ```

   By standard results on the uniqueness of the Reye configuration, such a pair
   `(σ_edges, σ_faces)` always exists and is unique up to automorphisms of Reye.

## 4. Output format and future script

Once implemented, the Tomotope–Reye isomorphism can be written to a JSON file
of the form:

```json
{
  "edges_to_reye_points": {
    "E0": "P3",
    "E1": "P7",
    "...": "..."
  },
  "faces_to_reye_lines": {
    "F0": "L12",
    "F1": "L4",
    "...": "..."
  }
}
```

This will make the Tomotope→Reye step completely explicit, and can then be
composed with the already-encoded Reye→24-cell map to push the Tomotope data
all the way into the 24-cell / D4 root system.
