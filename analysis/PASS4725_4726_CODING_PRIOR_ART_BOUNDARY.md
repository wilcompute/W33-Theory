# Passes 4725–4726 — coding prior-art boundary

The literature search changes the novelty statement but does not change the exact theorem.

## Known before this project

W. H. Haemers, M. J. P. Peeters, and J. M. van Rijckevorsel, **Binary Codes of Strongly Regular Graphs**, *Designs, Codes and Cryptography* 17 (1999), 187–209, studied the binary codes generated by adjacency matrices of strongly regular graphs.

For the `SRG(40,12,2,4)` family, their Table 11 includes the two GQ(3,3) point graphs. Entry no. 23 has dimension 10 and weight enumerator

\[
1+40z^{12}+135z^{16}+672z^{20}+135z^{24}+40z^{28}+z^{40}.
\]

The paper also states that for no. 23 the forty rows of the adjacency matrix are precisely all codewords of weight 12.

Therefore the binary adjacency code called `H10` in this repository, including its `[40,10,12]` parameters and the enumerator above, is prior art. It must not be presented as a newly discovered code.

## What Passes 4721–4726 add

The repository's exact finite model adds the following W33-specific structure, which the literature source above does not supply:

1. the 1,620 support-12 apartment thickenings form 540 disjoint-support triangles;
2. their four-line complements collapse 2-to-1 onto 270 residues;
3. those 270 residues are exactly the four-fixed-line sets of the size-270 inner involution class;
4. the 540 triangles are PSp(4,3)-equivariantly identified with the 540 four-fixing outer order-four square roots, with both mapping 2-to-1 to the 270 residues/involutions;
5. the 270 residue masks span exactly `ker_F2(A_*) = H10^perp`;
6. the 270 residues are the complete weight-4 shell of that `[40,30,4]` dual code and hence the complete minimum parity-check shell reconstructing H10.

The novelty claim is therefore the **involution/support-shell/dual-minimum identification and square-root cover**, not the existence of the underlying dimension-10 adjacency code.

## Additional search boundary

A separate published ternary `[40,30,4]_3` code with 260 weight-4 words occurs in work on designs from `S_4(3)`/`L_4(3)`; it is the projective-geometry code of `PG(3,3)` and is unrelated to the binary `[40,30,4]` code here. The shared parameter triple must not be used to identify the two codes.
