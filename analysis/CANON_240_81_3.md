## Why this file exists

`scripts/rediscovery_sweep.py` measures that **22.9% of the corpus asserts a result
that already exists elsewhere, uncited**, and `[[240,81,3]]` is the single largest
cluster:

```text
[[240,81,3]] / [240,81,3]   →  51 live files, citing none of the others
```

That is not 51 independent derivations. It is one result quoted 51 times, and the
cost is that a reader cannot tell which file to believe, which is load-bearing, or
whether the distance was ever re-derived or only copied forward.

**If you are asserting `[[240,81,3]]`, cite this file or the owner directly.** That
is the whole ask, and it is also exactly what silences the guard warning.

## `[[240,81,4]]` is wrong — RESOLVED, and the evidence was in the owner all along

`analysis/BATCH_415_429_INTAKE_FINDINGS.md` recorded this as an **open** certified-value
contradiction, with an unticked box:

> *"One certified-value contradiction. The formula-universe file asserts `[[240,81,4]]`
> three times, against the certified `[[240,81,3]]`… plausibly a **d versus d_Z
> conflation**."*
> `- [ ] Disambiguate [[240,81,4]]: either correct to [[240,81,3]], or write d_Z=4
> explicitly, or name the superseded certificate.`

**The hypothesis was right, and the owner file proves it.**
`exploration/PART_CCCCIII_W33_CSS_DISTANCE.py` computes both distances separately and
asserts all three as checks:

```text
d_X = min wt(x) for x in ker(H_Z) \ row(H_X)   =  3     (checked, 160 weight-3 witnesses)
d_Z = min wt(z) for z in ker(H_X) \ row(H_Z)   =  4     (checked)
d   = min(d_X, d_Z)                            =  3     (checked)
```

So:

- **`[[240,81,3]]` is the code.** Distance is `min(d_X, d_Z)`, and that is 3.
- **`[[240,81,4]]` is not a code parameter.** It is `d_Z` promoted to the distance slot.
- `d_Z = 4` is a correct and useful quantity — write it as `d_Z`, never as the third
  entry of a `[[n,k,d]]` triple.

**Downstream consequence, flagged not fixed.** `analysis/BT1204_holonet_milestone_dashboard.md`
sets milestone **F4** as `[[240,81,4]]_3` with the acceptance criterion *"logical-error
suppression consistent with distance 4."* That criterion is mis-specified: the code
corrects to distance **3**. Either the milestone should read distance 3, or it should
