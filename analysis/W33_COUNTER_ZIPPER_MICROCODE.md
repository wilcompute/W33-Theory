# Counter instructions can now be interrupted inside a carry

The existing authenticated counter machine can verify an arbitrarily long
carry or borrow as one macro instruction. That makes macro-instruction fuel a
poor scheduling quantum: incrementing `2^4096-1` opens 4,096 bit nodes before
another guest can run. `w33_counter_zipper_microcode.py` refines that same ISA
into ticks that open at most one bit node and materialize at most one bit node.
The result is an executable integration, not a new zipper or universality theorem.

## Process and virtual hardware

The caller owns a trusted `MicroState`: the original committed state, both fibre
tags, a phase, and three content roots (`cursor`, `stack`, `result`). An untrusted
worker returns a JSON `MicroReceipt` with zero or one bit opening. A store-free
verifier authenticates that opening against the trusted continuation, computes
the next continuation and writes, and checks the claimed route. Only verified
writes enter the bit store. The next receipt must begin at that exact state.

| Phase | Action | Bit openings | Bit writes |
| --- | --- | --- | --- |
| SCAN | Read one carry/borrow digit; push a unary frame, or construct the pivot | 0 or 1 | 0 or 1 |
| UNWIND | Pop one frame and rebuild one digit; an empty stack advances phase | 0 or 1 | 0 or 1 |
| COMMIT | Emit the existing W33 portal route and finish the macro instruction | 0 | 0 |
| DONE | Expose the new committed macro state | 0 | 0 |

A frame is the canonical bit node `Bit(1, previous_stack)`. INC propagates over
ones and rebuilds zeros; DEC propagates over zeros and rebuilds ones. Thus the
stack records path length without converting the register to a host integer.
The original register roots and program counter remain unchanged during the
microsteps. DONE changes the selected register and branch exactly as the existing
macro verifier does. HALT and zero-branch DEC take one tick.

For a carry/borrow prefix of length k, scanning takes k ticks plus one pivot,
rebuilding takes k ticks plus one empty-stack transition, and COMMIT takes one:
`2k+3`. Every finite canonical counter has a finite prefix, so these internal
steps terminate. Hiding them gives the existing macro execution: a stuttering
refinement. The scalable two-counter model supplies the universality argument;
the finite W33 controller and the finite hash-address implementation alone do
not establish an infinite-memory physical machine.

## Measured witnesses

`w33_counter_zipper_microcode_certificate.json` is regenerated by the executable.

| Operation | Existing macro openings | Microticks | Maximum openings / writes per tick |
| --- | ---: | ---: | ---: |
| INC on `2^4096-1` | 4096 | 8195 | 1 / 1 |
| DEC on `2^4096` | 4097 | 8195 | 1 / 1 |
| INC on a large even counter | 1 | 3 | 1 / 1 |

512 cases (both operations, both registers, values 0 through 127) match a macro
oracle using an independent bit store. Addition `(7,11)` reaches `(18,0)` and
halts after the same 24 macro instructions. In a one-tick round robin, INC 14
commits after three rounds while the long carry has committed no instruction.
This demonstrates bounded node-access quanta, not a wall-clock latency bound.

## An interrupted instruction is also a storage obligation

A paused DEC on `2^16` after eight scan ticks has 17 nodes reachable from the
committed registers but 24 reachable from the complete continuation. Collecting
only the committed roots destroys the zipper stack even though the guest has
not changed its visible state. The correct root set contains both committed
registers, cursor, stack and result; both fibre tags travel with the control.

The reference checkpoint serializes this exact closure and the continuation.
The example occupies 4,994 canonical JSON bytes. Recovery requires a caller-owned
trusted continuation identity, verifies each node address and exact closure,
and rejects missing, duplicate, corrupt or unreachable nodes. The checkpoint
is not evidence that its history was executed: trust originates at genesis or
an already verified continuation.

The regression stores a checkpoint as an opaque content blob, pins it STRONG
through the existing temporal collector, discards the worker, then recovers and
finishes the borrow. Releasing that pin lets collection delete the checkpoint
even when its HASH_ONLY audit reference remains. This joins execution fuel to
the repo's existing distinction between content identity and retained bytes.

## Prior work and limits

The path-context idea specializes Gerard Huet's [The Zipper, JFP 7(5), 1997,
549-554](https://www.cambridge.org/core/journals/journal-of-functional-programming/article/zipper/0C058890B8A9B588F26E6D68CF0CE204)
([author PDF](https://gallium.inria.fr/~huet/PUBLIC/zip.pdf)). The repo already has
`w33_authenticated_counter_machine.py`, `w33_lossless_counter_suspension.py`,
`w33_temporal_merkle_gc.py` and `w33_shared_counter_archive.py`; this module reuses
their state identity, portal admission, canonical bit objects, fibre parser and
closure traversal. `W33_JOINT_SNAPSHOT_ADMISSION.md` handles shared archive
admission; its budget does not yet automatically include these microcheckpoints.
Searches for zipper and bounded carry/borrow continuation found no prior module;
result searches for 8195 and one opening per tick found this implementation.
That is a corpus check, not a worldwide novelty claim.

Bounds apply to bit-node openings and writes. Program validation is repeated by
`_admit`; program size, metadata integers, serialization, total work, wire size,
RAM, I/O, hashing and physical gates are not constant-cost claims. Checkpoints
are variable-sized full-closure snapshots. Recovery has explicit wire/node
limits. Operations assume a serialized owner and collision-free content names
within the finite run. There is no durable transaction, hostile-owner protection,
parallel commit protocol or formally checked liveness proof in this packet.

## Reproduce

```sh
python analysis/w33_counter_zipper_microcode.py
python tests/test_w33_counter_zipper_microcode.py
python tests/test_w33_authenticated_counter_machine.py
python tests/test_w33_lossless_counter_suspension.py
```

The nine new tests cover fresh-worker JSON recovery at every pause for both
carriers and shifted layouts, an independent macro oracle, actual store-access
counts with host encode/decode disabled, corrupted and stale receipts, premature
commit, exact checkpoint closure, STRONG/HASH_ONLY GC behavior, and fuel/wire
limits. Two initial test fixtures were corrected: session IDs must be digests,
and HALT moves to its assigned portal. Neither required changing the microcode.
