# Pass 384 — Q6-to-binary-Q3 coordinate folds do not canonize the header binding

Pass 377 built a finite binary-Q3 switch bank: its three one-bit control axes
reach a 48-flag header plane with axis-cycle profile

\[
[8,4,4].
\]

Pass 380 then showed that the live scheduler needs a phase-trit refinement to
share that free C3 clock, and Pass 381 supplied an explicit reviewed
sixteen-row binding table. The remaining question was narrower than a general
compiler problem:

> Can a **strict coordinate fold** from the six Q6 directions to the three
> binary-Q3 switch axes derive that binding, or even select one of its rows?

The answer for the current data is no. This is a finite control-address
result, not an assertion about an analogue oscillator, a physical device, or a
state-level Q6 traversal.

## The class being tested

A **strict coordinate fold** is the linear map

\[
L_f:\mathbb F_2^6\longrightarrow\mathbb F_2^3,\qquad
e_i\longmapsto e_{f(i)},\qquad f(i)\in\{1,2,3\}.
\]

It keeps a Q6 direction as a one-bit binary-Q3 control direction. A general
rank-three binary linear map may collapse a Q6 edge to zero or map it to a
multi-bit Q3 displacement, so it is intentionally outside this logic-switch
class.

There are

\[
(2^6-1)(2^6-2)(2^6-4)=234360
\]

rank-three binary linear maps, but only

\[
3^6-3\cdot2^6+3=540
\]

strict surjective coordinate folds. Under the evident
\(S_6\times S_3\) relabelling action, those 540 folds have exactly three
orbits:

| Target-preimage profile | Representative | Count | Stabilizer order |
|---|---:|---:|---:|
| \(4+1+1\) | `[1,1,1,1,2,3]` | 90 | 48 |
| \(3+2+1\) | `[1,1,1,2,2,3]` | 360 | 12 |
| \(2+2+2\) | `[1,1,2,2,3,3]` | 90 | 48 |

The eight affine offsets above each strict linear fold give 4,320 strict
affine coordinate folds. They add no new translation class once the map is
surjective.

## The live scheduler profile leaves six candidates

The GAP witness reads the BT1407 body schedule directly. In walk-coordinate
order \(0,\ldots,5\), its sixteen edge steps use the six Q6 directions with
frequency profile

\[
[3,2,2,3,4,2].
\]

It also reconstructs the Pass-377 header plane directly from the header
formula and verifies its `[24,12,12]` flag support and `[8,4,4]` C3-cycle
profile. Exactly six strict folds transform the live scheduler usage profile
to the header profile:

```
[1,1,2,1,3,2]   21/48 header-axis matches
[1,1,3,1,2,3]   21/48
[1,2,1,1,3,2]   15/48
[1,2,2,1,3,1]   22/48
[1,3,1,1,2,3]   18/48
[1,3,3,1,2,1]   21/48
```

The profile-preserving coordinate relabellings have nominal order 24. Their
induced action on this six-element set has order 12, is transitive, and has
point stabilizer order 2. So there is one profile-level candidate orbit, not
a distinguished fold.

The two natural Pass-380 anchors do not change that result. Scheduler flags
112 and 144 lie on walk coordinates 1 and 4 respectively (one-based), and
both lie on header axis 1. Every one of the six folds maps both coordinates
to axis 1.

## The live BT1371 table gives an exact no-go

BT1371's `q6_direction` is reverse-indexed relative to the walk bit:

\[
d\longleftrightarrow 5-d.
\]

Using that convention, the actual 48 Pass-377 header flags give this
direction-by-header-axis matrix, with rows \(d=0,\ldots,5\):

```
6 2 4
3 1 1
6 1 1
1 4 2
3 0 1
5 4 3
```

Every Q6 direction occurs under multiple header axes. Exhaustive GAP
enumeration therefore finds:

\[
\#\{\text{exact strict direction--axis intertwiners}\}=0.
\]

Even the best unrestricted strict fold agrees on only \(25/48\) flags, and
the unique best `[8,4,4]` profile fold,

```
[1,2,2,1,3,1],
```

agrees on only \(22/48\). It is a pinned-table optimization diagnostic, not canonical, and not a header-to-scheduler binding theorem.

There is a stronger C3 obstruction. On the header plane, take each observed
pair of Q6 directions under the arithmetic depth step

\[
f\longmapsto f+64\pmod {192}.
\]

The transpositions generated by those pairs form `S6`, of order 720, on all
six Q6 directions. Hence a direction coloring preserved by that header C3
step must be constant. GAP finds exactly three invariant colorings in all,
and zero invariant strict surjective folds.

## What coordinate data can and cannot supply

A chosen coordinate fold partitions the sixteen header C3 cycles into
\(8+4+4\), but it does not attach individual scheduler edge-orbits to
individual header cycles. The residual axis-respecting binding torsor is

\[
S_8\times S_4\times S_4
\]

with independent C3 phase offsets:

\[
8!(4!)^2\,3^{16}=999730823454720.
\]

After fixing the two oriented Pass-380 anchors, it remains

\[
6!(4!)^2\,3^{14}=1983592903680.
\]

If the six fold labels are retained as distinct candidates, the corresponding
anchored total is

\[
6\cdot6!(4!)^2\,3^{14}=11901557422080.
\]

This is a torsor of possible bindings given axis color alone; it is not claimed
to be an automorphism group of the complete scheduler data.

The five binary-Q3 source blocks of Pass 377 are also not a homogeneous
translation quotient of \(\mathbb F_2^6\): a translation action of that
elementary abelian 2-group has orbit sizes dividing 64, hence only powers of
two. This does not rule out an explicitly supplied nonuniform five-block
addressing function.

## Precise boundary

For the present BT1371 address table and Pass-377 header-axis labels:

- no strict surjective coordinate fold exactly intertwines Q6 direction with
  header binary-Q3 axis on all 48 header flags;
- no strict surjective coordinate fold is invariant under the header C3 depth
  step; and
- the two natural scheduler anchors do not choose among the six
  stress-compatible folds.

The result does not rule out an explicit sixteen-row binding table (Pass 381
provides one as reviewed input), a different flag-to-edge address table, or a
non-coordinate data-enriched map. It only prevents the current coordinate
fold class from being misrepresented as a canonical derivation of that
binding.
